# الكتيّب الرسمي — نظام الفحص القانوني الآلي (نسخة عامة قابلة للتداول)

> وثيقة جامعة: فكرة النظام + دليل الاستخدام الكامل + استخدام النتائج في كلود + خارطة التطوير.

> كل المخرجات مساعدة آلية تحتاج مراجعة المحامي. المعالجة محلية بالكامل.


---


# الجزء الأول: فكرة الكود وهدفه

## فكرة الكود وهدفه

### ما هذا النظام؟
نظام برمجي **لفحص مستندات القضايا القانونية آلياً** وتحويلها من أكوام ملفات (PDF
ممسوحة، Word، Excel، صور، أرشيفات مضغوطة) إلى **معرفة منظَّمة قابلة للقراءة والبحث
والمراجعة**: فهرس شامل، نصوص مقروءة، تقارير، خط زمني، وكيانات قانونية مستخرجة.

### المشكلة التي يحلّها
ملفات القضايا عادةً:
- كثيرة ومبعثرة وغير مفهرسة.
- ممسوحة ضوئياً بنصّ معكوس الاتجاه أو غير قابل للبحث.
- مكرّرة أو ناقصة أو داخل أرشيفات مضغوطة.
- يصعب على المحامي حصر «ماذا لدينا؟» و«أين؟» و«ما المفقود؟» بسرعة.

النظام يؤتمت هذا العبء: **يجرد، يقرأ، يصحّح، يستخرج، يصنّف، ويقرّر الجودة** — في دقائق.

### الفكرة الجوهرية (كيف يعمل)
1. **جرد وفهرسة:** حصر كل الملفات (أو فهرستها تلقائياً إن لم تكن مفهرسة).
2. **قراءة واستخراج:** قراءة النصوص من كل صيغة + OCR للصور والـPDF الممسوح + فكّ الأرشيفات.
3. **تصحيح القراءة:** كشف النص العربي المعكوس (الناتج عن المسح) وإعادته منطقياً عبر
   قياس «معقولية» كل سطر بقاموس عربي + مصطلحات القضية (تعلّم ذاتي من الإعداد والنص).
4. **الاستخراج القانوني:** الأطراف، أرقام القضايا والصكوك، التواريخ، المبالغ، المحاكم،
   الأنظمة والمواد.
5. **التصنيف والتنظيم:** نوع كل مستند + تقسيم بنيوي (ترويسة/أطراف/متن/طلبات).
6. **التحليل:** خط زمني، سجل صكوك، أسباب نقض، إحالات نظامية، مبالغ مركزية.
7. **المخرجات:** فهرس Excel + ملف Word لكل مستند + تقارير + JSON مهيكل.
8. **فحص الجودة:** تقرير آلي يقيس جودة قراءة كل ملف ويُبرز ما يحتاج انتباهاً.

### المبادئ التصميمية
- **عام لأي قضية:** المنطق مفصول عن بيانات القضية عبر ملف إعداد واحد `case_config.json`.
- **تعلّم ذاتي:** يستخرج أسماء أطراف القضية من الإعداد ومن النص نفسه ليقوّي نفسه بلا ضبط يدوي.
- **محلي بالكامل:** المعالجة على الجهاز؛ بيانات القضية لا تخرج لأي خدمة خارجية (سرية).
- **أمر واحد:** `legal_audit.py run <اسم_القضية>` يشغّل كل شيء.

### الهدف
- تسريع تجهيز ملف القضية للمراجعة من أيام إلى دقائق.
- ضمان عدم ضياع مستند أو تجاهل معلومة (أرقام صكوك/مبالغ/تواريخ).
- توفير أساس منظّم يبني عليه المحامي تحليله ومذكراته.

### حدّ إلزامي (قانوني وأخلاقي)
كل المخرجات **«مساعدة آلية تحتاج مراجعة المحامي»**، وليست رأياً قانونياً نهائياً.
وجودة المخرجات تتبع جودة المُدخلات؛ النظام يستخرج أفضل المتاح ويُعلّم النقص، ولا يختلق
ما ليس في المصدر، ولا يُعتمد نصّ نظامي دون تحقّق رسمي.

# الجزء الثاني: دليل الاستخدام الكامل

## دليل الاستخدام الكامل — نظام الفحص القانوني الآلي

نظام برمجي لفحص مستندات القضايا القانونية آلياً وإنتاج فهرس وتقارير وملفات قابلة
للقراءة والبحث والمراجعة. هذا الدليل يشرح كل شيء من التثبيت إلى المخرجات.

> تنبيه قانوني: كل المخرجات «مساعدة آلية تحتاج مراجعة المحامي»، وليست رأياً قانونياً
> نهائياً. المعالجة محلية بالكامل؛ بيانات القضية لا تخرج لأي خدمة خارجية.

---

### 1) فكرة النظام وهدفه
يحوّل أكوام الملفات (PDF ممسوحة، Word، Excel، صور، أرشيفات مضغوطة) إلى:
- فهرس شامل لكل المستندات.
- نصوص مقروءة (مع تصحيح اتجاه النص العربي الممسوح + OCR).
- استخراج الكيانات (أطراف، قضايا، صكوك، تواريخ، مبالغ، محاكم، أنظمة).
- تصنيف، خط زمني، سجل صكوك، أسباب نقض، إحالات نظامية.
- تقارير Word و Excel، وفحص جودة آلي.

الهدف: تسريع تجهيز ملف القضية من أيام إلى دقائق، وضمان عدم ضياع مستند أو معلومة.

---

### 2) المتطلبات والتثبيت

#### الطريقة (أ): Docker — تثبيت بأمر واحد (موصى به)
```
docker build -t legal-audit .
docker run --rm -v "$PWD:/app" legal-audit python3 scripts/legal_audit.py list
```

#### الطريقة (ب): يدوياً
أدوات النظام:
```
tesseract-ocr  tesseract-ocr-ara  poppler-utils  unrar  p7zip-full
```
مكتبات بايثون:
```
pip install -r requirements.txt
```

---

### 3) بنية المشروع
```
scripts/                # الكود (المحرّك + الواجهة)
cases/<اسم القضية>/     # كل قضية مستقلة (للأداة المعمّمة)
  case_config.json      # إعداد القضية
  staging/
    docs/               # ضع هنا ملفاتك الحقيقية (PDF/Word/Excel/صور)
    raw/                # الأرشيفات (zip/rar) والصور للمعالجة وOCR
    text/               # النصوص المستخرجة (يولّدها النظام)
    study/              # (اختياري) دراسة/فهرس بروابط: source_study.docx
  outputs/              # النتائج (Excel/Word/CSV/JSON/تقارير)
```

---

### 4) التشغيل السريع (أمر واحد)
```
python3 scripts/legal_audit.py new قضيتي      # إنشاء قضية
## ضع المستندات في cases/قضيتي/staging/docs/
python3 scripts/legal_audit.py run قضيتي      # تشغيل الفحص الكامل
python3 scripts/legal_audit.py list           # عرض القضايا
```
أمر `run` يشغّل تلقائياً بالترتيب: فهرسة ← فكّ ضغط/OCR ← تصحيح القراءة ← اكتشاف
الأطراف ← استخراج وتصنيف ← تحليل ← تقارير Word/Excel ← فحص الجودة ← حزمة المخرجات.

---

### 5) سير العمل التفصيلي

#### 5-أ) قضية جديدة
1. `new قضيتي`.
2. ضع الملفات في `staging/docs/` (الأسهل — عناوين حقيقية)، أو نصوصاً جاهزة في
   `staging/text/<id>.txt`، أو أرشيفات/صور في `staging/raw/`.
3. عدّل `case_config.json` (اختياري لكنه يقوّي الدقّة).
4. `run قضيتي`.

#### 5-ب) إضافة ملفات لقضية قائمة (إلحاق)
1. ضع الملفات الجديدة فقط في `staging/docs/` (أو `staging/raw/`).
2. أعد `run قضيتي`.
النظام يفهرس الجديد فقط ويُلحقه دون تكرار أو فقدان القديم.

#### 5-ج) أنواع المدخلات المقبولة
- مستندات حقيقية بعناوينها: `staging/docs/`  (PDF, DOCX, XLSX, CSV, TXT).
- أرشيفات وصور: `staging/raw/`  (ZIP, RAR, 7Z, JPG, PNG, PDF ممسوح).
- نصوص جاهزة: `staging/text/<id>.txt`.
- بيانات وصفية جاهزة (اختياري): `staging/parts/*.jsonl`.
- دراسة/فهرس بروابط (اختياري): `staging/study/source_study.docx`.

---

### 6) ملف الإعداد case_config.json
```json
{
  "case": {"number": "رقم القضية", "title": "اسم القضية", "case_folder_name": "اسم المجلد"},
  "deed_numbers_known": ["أرقام الصكوك المعروفة"],
  "parties": {"اسم الطرف": ["أنماط مطابقة الاسم"]},
  "other_actors": {"وكيل/خبير/قاضٍ": ["أنماط"]},
  "company_patterns": ["اسم الشركة/الجهة"]
}
```
يمكن تركه شبه فارغ؛ النظام يكتشف أسماء الأطراف من النص تلقائياً أيضاً.

---

### 7) المخرجات (داخل cases/<القضية>/outputs)

#### Excel
`excel/00_master_documents.xlsx` — الفهرس الرئيسي، وفيه ورقتان:
- «كل المستندات»: رابط Drive + رابط Word + التاريخ + النوع + ملخص آلي لكل مستند.
- «بطاقات التعريف»: جدول موحّد لترويسات كل المستندات (الجهة/الدائرة/القضية/الصك/
  التاريخ/الأطراف/المبالغ) + رابط Word.

ملفات Excel أخرى للكيانات والتصنيف والمقارنة والتحقق النظامي.

#### Word
- `word/00_ملخص_القضية.docx` — الموجز التنفيذي.
- `word/documents/` — ملف Word لكل مستند، يبدأ بـ«بطاقة تعريف المستند» ثم النص
  مقسّماً لأقسام معنونة (ترويسة/أطراف/متن/طلبات).
- `word/10_all_key_tables.docx` و`word/11_extracted_documents_text.docx`.

#### CSV (جداول قابلة للفتح مباشرة)
الجرد، الكيانات، التصنيف، أسباب النقض، الصكوك، المحطات، المبالغ، الإحالات النظامية،
المقارنة مع الدراسة، فحص الجودة (`14_readability_qc.csv`).

#### JSON
`json/full_audit_data.json` — كل البيانات المهيكلة (مفيد لكلود والتحليل البرمجي).

#### تقارير Markdown
الموجز، تقرير الفحص الأولي، الخط الزمني وأسباب النقض، قائمة مراجعة المحامي.

---

### 8) بطاقة تعريف المستند
تظهر أعلى كل ملف Word وفي ورقة Excel، وتبسّط الترويسة المختلفة الشكل إلى حقول موحّدة:
نوع المستند، الجهة المصدِرة، الدائرة، رقم القضية، رقم الصك/الحكم، التاريخ، الأطراف،
مبالغ بارزة. تُستخرج من أعلى المستند والعنوان لتفادي الأرقام المُشار إليها في المتن.

### 10) الميزات الذكية (تعمل تلقائياً)
- تصحيح اتجاه النص العربي الممسوح (يميّز المعكوس ويعيده منطقياً).
- OCR عربي للصور وPDF الممسوح، وإعادة OCR بدقة أعلى عند ضعف الجودة.
- فكّ الأرشيفات (zip/rar/7z) وقراءة محتواها.
- تعلّم ذاتي: يضيف أسماء أطراف القضية من الإعداد ومن النص لتقوية الدقّة.
- إلحاق تدريجي: يضيف الملفات الجديدة دون فقد القديم.
- بطاقة تعريف موحّدة لكل مستند.

---

### 11) الاستخدام مع وكيل ذكاء أو محادثة كلود
- التشغيل الفعلي يحتاج **وكيلاً برمجياً** (مثل Claude Code) أو جهازاً عليه بايثون.
- محادثة كلود العادية (claude.ai) لا تشغّل الكود؛ تصلح **لتحليل المخرجات** بعد توليدها:
  ارفع الملفات النصية الصغيرة (التقارير + الجداول + JSON) في مشروع كلود واسأل عليها.

---

### 12) تعدّد القضايا
كل قضية مجلد مستقل تحت `cases/`. المحرّك مشترك. للتبديل: استخدم اسم القضية في الأوامر.

---

### 13) الخصوصية والامتثال
- معالجة محلية بالكامل (لا تخرج البيانات).
- يُنصح بتشفير القرص وضبط صلاحيات الوصول.
- التحقق من النصوص النظامية من مصادرها الرسمية قبل الاعتماد.

---

### 14) استكشاف الأخطاء
- نصّ ضعيف لملف ممسوح؟ ضع نسخته PDF في `staging/raw/` وأعد التشغيل (OCR 300DPI).
- ملف بلا عنوان واضح؟ سمِّه باسم معبّر في `staging/docs/`.
- أرشيف كبير (>10MB)؟ ضعه مباشرةً في `staging/raw/` على جهازك (لا قيود تنزيل محلياً).
- راجع `outputs/csv/14_readability_qc.csv` لمعرفة الملفات التي تحتاج انتباهاً.

---

### 15) الحدود والتنبيهات
- جودة المخرجات تتبع جودة المُدخلات؛ النظام يستخرج أفضل المتاح ويُعلّم النقص ولا يختلق.
- بطاقة التعريف والتصنيف مساعدات استرشادية تحتاج تأكيد المحامي.
- الشعارات/التذييلات المزخرفة في المسح قد تبقى غير واضحة (بلا محتوى قانوني).

# الجزء الثالث: استخدام النتائج في محادثة كلود

دليل استخدام نتائج القضية داخل محادثة كلود
=================================================

أولاً: تجهيز الملفات (مرة واحدة)
--------------------------------
الخطوة 1: نزِّل ملف «حزمة المحادثة» الذي أرسلتُه لك.
الخطوة 2: انقر عليه بزر الفأرة الأيمن، ثم اختر «استخراج الكل» (فكّ الضغط).
الخطوة 3: سيظهر لك مجلد بداخله أربعة عشر ملفاً نصياً صغيراً (تقارير وجداول).


ثانياً: إنشاء مساحة عمل دائمة للقضية (الطريقة المفضّلة)
-------------------------------------------------------
الخطوة 1: ادخل إلى موقع كلود من المتصفّح.
الخطوة 2: من القائمة الجانبية، أنشئ مشروعاً جديداً وسمِّه: «أي قضية».
الخطوة 3: ادخل المشروع، ثم ارفع ملفات «حزمة المحادثة» في قسم معرفة المشروع.
الخطوة 4: الآن أي محادثة جديدة داخل هذا المشروع تستطيع أن تسأل فيها مباشرة،
         وكلود يرى كل التقارير والجداول دون إعادة رفعها في كل مرة.


ثالثاً: السؤال عن مستند واحد بعينه
-----------------------------------
الخطوة 1: افتح محادثة عادية.
الخطوة 2: ارفع ملف الوورد الخاص بذلك المستند فقط (من مجلد مستندات الوورد).
الخطوة 3: اكتب سؤالك عن هذا المستند تحديداً.


رابعاً: أمثلة جاهزة للأسئلة (انسخها كما هي)
--------------------------------------------
1) رتّب أسباب النقض من الأقوى إلى الأضعف نظاماً، مع تعليل مختصر لكل سبب.
2) اصنع سرداً زمنياً موجزاً للقضية في صفحة واحدة اعتماداً على جدول المحطات.
3) قارن بين الحكم الابتدائي وحكم الاستئناف، ووضّح أوجه التناقض إن وُجدت.
4) لخّص نزاع التقييم بين المبالغ المختلفة وأثره على موقف الطرفين.
5) اكتب مسودة مذكرة نقض موجَّهة للمحكمة العليا استناداً إلى الأسباب والمستندات.
6) ما المستندات الناقصة أو المحذوفة التي قد تؤثر على الموقف القانوني؟


خامساً: قواعد مهمة لتجنّب المشاكل
----------------------------------
1) لا ترفع الحزمة الكاملة الكبيرة في المحادثة؛ ارفع «حزمة المحادثة» الصغيرة فقط.
2) لا ترفع كل ملفات الوورد دفعة واحدة؛ ارفع ما تحتاجه فقط.
3) كل ما ينتجه كلود مساعدة آلية تحتاج مراجعتك القانونية، وليست رأياً نهائياً.

# الجزء الرابع: خارطة تطوير المنتج

## خارطة طريق تحويل النظام إلى منتج برمجي قانوني قابل للتداول

`[وثيقة تخطيطية — وضعها الحالي: مسوّدة للنقاش]`

### 1) الخلاصة
النظام الحالي **نواة منتج جاهزة**: المنطق عام بالكامل ومفصول عن بيانات القضية عبر ملف
إعداد واحد (`case_config.json`)، ويُشغَّل بأمر واحد (`run_all.sh`). تحويله إلى منتج
قابل للتداول مع المختصين (محامون، مكاتب، إدارات قانونية) **ممكن وواقعي** ويحتاج طبقات
تغليف وواجهة وامتثال، لا إعادة بناء.

### 2) ما الجاهز فعلاً (أصول المنتج)
- محرك فحص آلي: جرد، استخراج كيانات (أطراف/قضايا/صكوك/تواريخ/مبالغ/محاكم/أنظمة).
- تصحيح اتجاه النص العربي الممسوح + OCR (عربي/إنجليزي) + فكّ الأرشيفات.
- تصنيف المستندات والمقاطع، خط زمني، سجل صكوك، أسباب نقض، إحالات نظامية.
- مخرجات: فهرس Excel، ملف Word لكل مستند بأقسام معنونة، تقارير، JSON مهيكل.
- فحص جودة آلي لكل ملف، ونظام إعداد لكل قضية + أمر تشغيل واحد.

### 3) الفجوات حتى يصبح «منتجاً قابلاً للتداول»
| الطبقة | المطلوب | الأولوية |
|---|---|---|
| التغليف | حزمة تثبيت بأمر واحد (مثبّت/حاوية Docker) تشمل أدوات النظام | عالية |
| تعدّد القضايا | بنية `cases/<اسم>/` لكل قضية بإعدادها ومخرجاتها مستقلة | عالية |
| الواجهة | واجهة استخدام بسيطة (سطر أوامر موجّه أو واجهة ويب محلية) | عالية |
| الخصوصية والامتثال | معالجة محلية بالكامل، عدم تسريب بيانات، توافق نظام حماية البيانات (PDPL) | حرجة |
| التحقق القانوني | تكامل اختياري مع مصادر رسمية للتحقق من الأنظمة (يدوي حالياً) | متوسطة |
| الجودة والاختبار | اختبارات آلية + قياس دقة الاستخراج على عيّنات | متوسطة |
| التوثيق والدعم | دليل مستخدم، أمثلة، فيديو، رخصة استخدام واضحة | متوسطة |

### 4) المسار المقترح (مراحل)
- **المرحلة 0 (جاهزة):** أداة سطر أوامر تعمل لقضية واحدة بإعداد. ✅
- **المرحلة 1 — تغليف وتعدّد قضايا:** حاوية Docker + بنية `cases/` + مثبّت واحد.
- **المرحلة 2 — واجهة محلية:** واجهة ويب بسيطة (رفع ملفات → تشغيل → عرض الفهرس والتقارير).
- **المرحلة 3 — مساعد تحليلي:** ربط اختياري بنموذج لغوي لإنتاج مسوّدات (مذكرات/ملخصات)
  مع إبقاء المبدأ: «مخرج آلي يحتاج مراجعة المحامي».
- **المرحلة 4 — منتج للتداول:** ترخيص، تسعير، دعم، تحديثات، وتوافق امتثالي موثّق.

### 5) اعتبارات قانونية وأخلاقية (إلزامية للمنتج القانوني)
1. كل المخرجات «مساعدة آلية» وليست رأياً قانونياً نهائياً — يجب إبراز هذا في الواجهة.
2. سرية ملفات القضايا: معالجة محلية، تشفير التخزين، صلاحيات وصول، سجل تدقيق.
3. التحقق من النصوص النظامية من مصادرها الرسمية قبل الاعتماد.
4. وضوح حدود الأداة (جودة OCR، احتمالات الخطأ) في كل تقرير.

### 6) نماذج التداول الممكنة
- أداة داخلية لمكتب/إدارة قانونية (ترخيص داخلي).
- منتج برمجي يُباع للمكاتب (تثبيت محلي للحفاظ على السرية).
- خدمة مُدارة (تتطلب ضمانات امتثال أعلى).

### 7) الخطوة التالية المقترحة
بناء **المرحلة 1**: إعادة هيكلة إلى حزمة قابلة للتثبيت + بنية `cases/` متعددة القضايا +
مثبّت واحد (Docker)، مع إبقاء كل الوظائف الحالية كما هي.

> ملاحظة: هذه الوثيقة تخطيطية؛ التنفيذ الفعلي يحتاج قراراً بالنطاق والموارد.
