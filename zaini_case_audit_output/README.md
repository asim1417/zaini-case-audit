## ما الذي يفعله المشروع
جرد آلي ومنهجي لمستندات القضية، وقراءة النصوص، واستخراج الكيانات القانونية
(الأطراف، أرقام القضايا، الصكوك، التواريخ، المبالغ، المحاكم، الأنظمة)، وتصنيف
المقاطع والمستندات، والمقارنة مع فهرس الدراسة، وإنتاج تقارير وجداول قابلة للمراجعة.

## كيفية التشغيل
```bash
# الوضع الافتراضي في هذه البيئة: بيانات مُرحّلة من Google Drive عبر MCP
python3 scripts/audit_zaini_case.py --staging staging

# وضع بديل: مجلد محلي فيه نسخ الملفات (PDF/DOCX/XLSX/CSV/TXT/صور)
python3 scripts/audit_zaini_case.py --root /path/to/local/folder
```

## بنية المجلد
- `scripts/audit_zaini_case.py` — السكريبت الرئيسي.
- `staging/parts/*.jsonl` — بيانات وصفية لكل ملف/مجلد (ناتج زحف Drive).
- `staging/text/<id>.txt` — النص المستخرج لكل ملف قابل للقراءة.
- `outputs/excel/` `outputs/csv/` `outputs/json/` `outputs/markdown/` — المخرجات.
- `outputs/word/` — **نسخ Word (.docx) قابلة للتعديل وسهلة القراءة (عربية RTL):**
  التقارير الأربعة + مستند الجداول الرئيسية (`10_all_key_tables.docx`) + مستند موحّد
  بكل النصوص المستخرجة (`11_extracted_documents_text.docx`، 181 مستنداً)، إضافةً إلى
  `outputs/word/documents/` (ملف Word مستقل بالنص الكامل لكل مستند، 179 ملفاً، دون قصّ).
- `outputs/excel/00_master_documents.xlsx` — **الفهرس الرئيسي**: صف لكل مستند
  (رابط Drive + رابط ملف Word للنص الكامل + التاريخ + القسم + النوع + ملخّص آلي +
  مقتطف النص). أفضل نقطة انطلاق للمراجعة.
- `logs/` — سجل التشغيل والتبعيات الناقصة.
- `unreadable/` — قائمة الملفات غير المقروءة/التي تحتاج OCR (دون نقل الأصول).

## أهم القيود والملاحظات (مهمة للمراجعة البشرية)
1. **الوصول إلى Drive عبر MCP فقط** — لا يوجد mount محلي؛ السكريبت لا يصل إلى Drive
   مباشرة، بل يعالج بيانات مُرحّلة جُمعت عبر أدوات MCP إلى مجلد `staging`.
2. **استعادة الجرد الكامل عبر روابط الدراسة** — جرى استخراج 192 رابط ملف + 18 رابط
   مجلد من ملف الدراسة، والوصول للملفات عبر معرّفاتها المباشرة (تجاوزاً لمجلدات ظهرت
   فارغة عبر الواجهة). **الجرد النهائي: 192 ملفاً عبر 18 قسماً.**
3. **معالجة الملفات الثنائية المعقّدة** (`process_binaries.py`):
   - فُكّت 10 ملفات مضغوطة (zip/rar) وقُرئت **130 ملفاً داخلياً** (كشوف Excel مالية…).
   - شُغّل **OCR** (tesseract ara+eng) على الصور وملفات PDF الصورية.
4. **التغطية النصية النهائية: 179 من 192 ملفاً مقروءة.** المتبقّي 13 ملفاً فقط
   (حدود صلبة لا يمكن تجاوزها بالأدوات المتاحة):
   - **8 ملفات مضغوطة كبيرة (10–140MB)** تتجاوز حدّ/مهلة تنزيل أداة MCP (نجح التنزيل
     حتى ~3.4MB فقط؛ وكل ما ≥10MB يعيد "session expired" حتى بجلسة جديدة، و140MB
     يصطدم بسقف 200MB للوسيط)؛ تحتاج **تنزيلاً يدوياً** ثم تشغيل `process_binaries.py`
     محلياً: القروض، المسحوبات 1431/1432/1433، مزرعة 1431/1432، فلة 1431/1432.
   - **5 روابط في الدراسة تعيد "Entity not found"** (ملفات محذوفة/غير متاحة) — مؤشر
     يطابق فئة «مذكور في الدراسة وغير موجود»: تقرير صلاح الحجيلان، تفاصيل/موعد دعوى
     (مرتان)، تقديم التماس إعادة نظر، تقرير جلسة القضية.
   - تم بنجاح **OCR لملف PDF الصورة** (طلب النقض الأخير ـ رقم الطلب 4714689866 ـ محال
     إلى المحكمة العليا).
5. **ملف الدراسة مُدمج**: `staging/study/source_study.docx` + النص الكامل، وتمت
   المقارنة بالمعرّفات وإدراج خلاصة الدراسة الذاتية (53 بنداً / 14 / 8).
6. لإعادة الإنتاج: شغّل `build_study_index.py` ثم `audit_zaini_case.py`. لمعالجة
   الثنائيات: نزّل الأرشيف/الصور إلى `staging/raw/` ثم شغّل `process_binaries.py`.
