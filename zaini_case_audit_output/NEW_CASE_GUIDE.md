# دليل استخدام النظام لأي قضية جديدة (نظام قابل لإعادة الاستخدام)

`[مخرج آلي / Script Output - سماوي]` `[مخرج آلي يحتاج مراجعة بشرية - وردي]`

هذا النظام **عام وقابل لإعادة الاستخدام**: المنطق كله (قراءة، تطبيع، تصحيح اتجاه النص،
استخراج الكيانات، التصنيف، الخط الزمني، التقارير، Word/Excel، فحص الجودة، الأمر الواحد)
لا يعتمد على قضية بعينها. **الخاص بكل قضية** محصور في ملف إعداد واحد: `case_config.json`.

## ما الذي يتغيّر لكل قضية؟ فقط `case_config.json`
```json
{
  "case": { "number": "رقم القضية", "title": "اسم القضية", "case_folder_name": "اسم مجلد Drive" },
  "deed_numbers_known": ["أرقام الصكوك/الأحكام المعروفة"],
  "parties": { "اسم الطرف": ["أنماط مطابقة الاسم"] },
  "other_actors": { "اسم الوكيل/الخبير/القاضي": ["أنماط"] },
  "company_patterns": ["اسم الشركة/الجهة محل النزاع"]
}
```
تُقرأ هذه القيم تلقائياً (عبر متغيّر البيئة `CASE_CONFIG`، أو من جذر المخرجات، أو من `staging/`).

## خطوات تشغيل قضية جديدة (3 خطوات)
1. **جهّز النصوص**: ضع نصوص/بيانات مستندات القضية في:
   - `staging/text/<id>.txt` (النص الخام لكل ملف)
   - `staging/parts/*.jsonl` (بيانات وصفية: id, title, mimeType, fileExtension, fileSize, dates, viewUrl, parentId …)
   - (اختياري) `staging/study/source_study.docx` إن وُجدت دراسة بروابط مباشرة للملفات.
   - (اختياري) `staging/raw/<id>.<ext>` لأي أرشيفات/صور (zip/rar/jpg) لمعالجتها بـ`--with-binaries`.

   > في بيئة هذه القضية جُمعت النصوص عبر أدوات Google Drive MCP. لأي قضية: يمكن جمعها
   > بنفس الطريقة، أو وضع مجلد محلي وتشغيل `audit_case.py --root <مجلد>` مباشرةً.

2. **اكتب `case_config.json`** بمعطيات القضية (انسخ الموجود وعدّله).

3. **شغّل الأمر الواحد**:
   ```bash
   bash scripts/run_all.sh                 # تشغيل كامل
   bash scripts/run_all.sh --with-binaries # مع فكّ ضغط الأرشيفات + OCR
   ```

## ماذا تحصل؟ (نفس مخرجات قضية زيني، لكن لقضيتك)
- `outputs/excel/00_master_documents.xlsx` — فهرس كل المستندات (رابط + تاريخ + ملخص + نص + إتاحة).
- `outputs/word/00_*.docx` — الموجز والتقارير + `outputs/word/documents/` ملف لكل مستند.
- `outputs/csv/*` — الكيانات، التصنيف، الخط الزمني، الصكوك، الأسباب، الإحالات، فحص الجودة.
- `outputs/json/full_audit_data.json` — كل البيانات المهيكلة.

## القوالب العامة (مشتركة بين كل القضايا — لا تحتاج تعديلاً عادةً)
داخل `scripts/audit_case.py` توجد قوائم عامة للقضاء السعودي يمكن تعديلها عند الحاجة
(أو نقلها إلى `case_config.json` بمفاتيح `courts`):
- **المحاكم/الدوائر** (`COURTS`)، **أسماء الأنظمة** (`LAW_NAME_KEYWORDS`)،
  **قواعد نوع المستند** (`DOC_TYPE_RULES`)، **قواعد تصنيف المقاطع** (`SEGMENT_RULES`)،
  **قاموس اتجاه النص** (`DICT` في `improve_readability.py`).

## السكربتات (وحدات مستقلة)
| السكربت | الوظيفة |
|---|---|
| `improve_readability.py` | تصحيح اتجاه النص المعكوس (سطراً بسطر، عبر القاموس) |
| `build_study_index.py` | بناء فهرس موثوق من دراسة بروابط (اختياري) |
| `audit_case.py` | الفحص: استخراج وتصنيف (config-driven) — يدعم `--staging` و`--root` |
| `analyze_case.py` | خط زمني + أسباب نقض + مبالغ + إحالات |
| `case_brief.py` | موجز موحّد + سجل الصكوك + المحطات |
| `process_binaries.py` | فكّ ضغط zip/rar/7z + OCR (tesseract ara+eng) |
| `make_word.py` / `make_master_excel.py` | مخرجات Word و Excel |
| `qc_readability.py` | فحص جودة القراءة لكل ملف |
| `run_all.sh` | **أمر واحد** يشغّل كل ما سبق |
