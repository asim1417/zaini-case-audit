# خدمة الفحص القانوني الآلي — دليل التكامل (لمنصة حكيم أو أي منصة)

خدمة REST API تحوّل وثائق قضية (PDF/صور ممسوحة) إلى حزمة منظّمة: فهرس + بطاقات +
تفريغ نصّي + ملحق مالي + تقارير. **محلية بالكامل**؛ لا تخرج البيانات لأي طرف خارجي.

## لماذا API + Docker (التوصية)
- المنصة تستدعي الخدمة عبر HTTP بأي لغة، دون ربط تقني.
- Docker يحزم كل المتطلبات (Tesseract العربي، Poppler، LibreOffice، خطوط عربية).
- تعمل داخل شبكتكم/استضافتكم؛ سرّية القضايا محفوظة.
- نمط مهام غير متزامن يناسب المعالجة الثقيلة (دقائق لكل قضية).

## النشر على استضافتكم
```
# بناء الصورة (من جذر المستودع)
docker build -t legal-audit-service -f service/Dockerfile .

# التشغيل (مع حجم دائم للمهام + مفتاح API اختياري)
docker run -d --name legal-audit -p 8080:8080 \
  -v /srv/legal-jobs:/data/jobs \
  -e API_KEY="ضع-مفتاحاً-سرياً" \
  legal-audit-service
```
> الصحّة: `GET http://HOST:8080/health` · التوثيق التفاعلي: `GET /docs`.

## نقاط الخدمة (Endpoints)
| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET  | `/health` | فحص جاهزية الخدمة |
| POST | `/jobs` | رفع ملفات الوثائق → إنشاء مهمّة (يعيد `job_id`) |
| POST | `/jobs/from-drive` | جلب الملفات من Google Drive / OneDrive برابط مشاركة → إنشاء مهمّة (انظر `README_CLOUD_DRIVES.md`) |
| POST | `/drive/list` | معاينة ملفات رابط سحابي قبل الجلب (بلا تنزيل) |
| GET  | `/jobs/{job_id}` | حالة المهمّة: `queued / downloading / running / done / error` |
| GET  | `/jobs/{job_id}/result` | تنزيل حزمة المخرجات (ZIP) عند `done` |
| GET  | `/jobs/{job_id}/log` | سجل المعالجة |

المصادقة (اختيارية): إذا ضُبط `API_KEY`، مرّر ترويسة `X-API-Key`.

## مثال استدعاء (من المنصة)
```
# 1) رفع الوثائق
curl -s -X POST http://HOST:8080/jobs \
  -H "X-API-Key: $KEY" \
  -F "files=@doc1.pdf" -F "files=@doc2.pdf"
# → {"job_id":"ab12cd34ef56","status":"queued"}

# 2) متابعة الحالة
curl -s http://HOST:8080/jobs/ab12cd34ef56 -H "X-API-Key: $KEY"
# → {"status":"running", ...}  ثم  {"status":"done","docs":42}

# 3) تنزيل الحزمة
curl -s -o package.zip http://HOST:8080/jobs/ab12cd34ef56/result -H "X-API-Key: $KEY"
```

## محتوى حزمة المخرجات (ZIP)
- `حزمة_الوثائق.docx` / `.pdf` — الحزمة الكاملة (فهرس جدولي + بطاقات + تفريغ).
- `حزمة_الوثائق_جزءN_*.docx` — أجزاء مقسّمة حسب النوع.
- `الملحق_المالي.docx/.xlsx` — التقييمات والمصاريف بجداول مبالغ.
- `الفهرس_الموحد.xlsx/.csv` ، `بطاقات_الوثائق.json/.xlsx` ، تقارير الجودة/التشوّه/التكرار.

## التكامل مع منصة حكيم (نمط مقترح)
1. المنصة تتيح للمستخدم رفع ملفات القضية → ترسلها إلى `POST /jobs`.
2. تخزّن `job_id`، وتستعلم دورياً عن الحالة (أو عبر Webhook لاحقاً).
3. عند `done` تنزّل ZIP وتعرض/تخزّن الحزمة في ملف القضية لدى المستخدم.
4. تُعرض المخرجات داخل واجهة المنصة (الفهرس/البطاقات/التفريغ).

## ملاحظات تشغيلية
- **الخطوط**: المستندات تستخدم اسم خط «Traditional Arabic» (متوفّر على أجهزة Windows/Word).
  على الخادم لتصدير PDF تُستبدل تلقائياً بخط عربي حر (Amiri) المثبّت في الحاوية — العرض سليم.
- **الموارد**: المعالجة وOCR كثيفة المعالج. ابدأ بعامل واحد، وزِد العمّال/المعالجات حسب الحِمل.
  للملفات الكبيرة (>2000 صفحة) عالِج على دفعات.
- **التخزين**: يُحفظ كل شيء تحت `/data/jobs/<job_id>` — نظّفه دورياً وفق سياسة الاحتفاظ.
- **التنبيه القانوني**: كل المخرجات «مساعدة آلية تحتاج مراجعة المحامي»، وليست رأياً نهائياً.

## حدود وتحسينات مستقبلية
- إضافة Webhook لإشعار المنصة عند الاكتمال (بدل الاستعلام الدوري).
- طابور مهام خارجي (Redis/RQ) لتوسّع أفقي عبر عدّة عمّال/خوادم.
- محرّك OCR سحابي اختياري (Azure/Google) عبر مفتاح صريح للصفحات الأصعب.

## محرّك اختياري: Datalab «lift» (استخراج مهيكل عالي الدقّة)
نموذج رؤية مفتوح الأوزان (9B) يقرأ PDF/صورة ويعيد JSON مطابقاً لـschema، مع **الامتناع**
(يعيد `null` بدل اختلاق الحقول الغائبة) — متوافق مع مبدأ المنظومة «لا تختلق».

- **متى يُفعّل**: اضبط `ENGINE_MODE=lift` (الافتراضي `tesseract` على CPU).
- **المتطلّبات**: **GPU** (~16–24GB) + تثبيت النموذج: `pip install lift-extract` (انظر `github.com/datalab-to/lift`).
- **الترخيص**: OpenRAIL-M معدّل — مجاني للبحث/الشخصي/الشركات < 5M$ إيراد؛ تحقّق قبل الاستخدام التجاري.
- **الدور في المنظومة**: يُحسّن **البطاقة المهيكلة والمبالغ المالية** (عبر `engine/lift_engine.py`)؛
  ويبقى التفريغ الحرفي عبر OCR (لتفادي إعادة الصياغة في النصّ الطويل).
- **التراجع الآمن**: إن لم يُفعّل أو تعذّر تحميله، يستمر المسار الحالي (Tesseract) دون أي خلل.

```
docker run -d -p 8080:8080 --gpus all \
  -e ENGINE_MODE=lift -e LIFT_MODEL=datalab-to/lift \
  -v /srv/legal-jobs:/data/jobs legal-audit-service
```
> اختبر على عيّنة عربية قانونية قبل الاعتماد (المعيار المعلن عام/إنجليزي غالباً).

## محرّك سحابي اختياري: Azure AI Document Intelligence (قراءة عالية الجودة)
خدمة Microsoft لقراءة الوثائق (عربي + جداول + تخطيط) بدقّة تفوق سقف Tesseract المحلي.

- **⚠️ سحابي**: تفعيله يرسل الوثائق إلى Azure (تخرج من البيئة المحلية). استخدم منطقة متوافقة
  وفعّل سياسة عدم استخدام البيانات للتدريب. لا يُفعَّل إلا صراحةً.
- **التفعيل** (متغيّرات بيئة على الخادم — لا توضع في الكود):
  ```
  ENGINE_MODE=azure
  AZURE_DI_ENDPOINT=https://<المورد>.cognitiveservices.azure.com/
  AZURE_DI_KEY=<المفتاح>          # الأفضل Managed Identity في الإنتاج
  AZURE_DI_MODEL=prebuilt-read     # أو prebuilt-layout للجداول
  ```
- **التثبيت**: `pip install azure-ai-documentintelligence`.
- **الدور**: يحلّ محلّ Tesseract لقراءة النص الحرفي عند تفعيله (أعلى جودة)؛ **تراجع آمن**
  للمحرّك المحلي عند أي تعذّر. الحقل `reocr.engine` يوثّق المحرّك المستخدم لكل وثيقة.
- **التشغيل بالحاوية**:
  ```
  docker run -d -p 8080:8080 \
    -e ENGINE_MODE=azure \
    -e AZURE_DI_ENDPOINT=... -e AZURE_DI_KEY=... \
    -v /srv/legal-jobs:/data/jobs legal-audit-service
  ```
> أولويات المحرّكات: `azure` (سحابي عالي الجودة) ← `lift` (مهيكل) ← `tesseract` (محلي افتراضي).
