# تقرير فنّي شامل — منظومة الفحص ومعالجة الوثائق القانونية العربية

> وثيقة تعريفية موجَّهة للمبرمج/الفريق التقني. تصف الغرض والمعمارية والآلية والخصائص
> والمتطلبات وكيفية التشغيل والتوسعة. كل المخرجات «مساعدة آلية تحتاج مراجعة قانونية».

---

## 1) نظرة عامة (ما هو النظام؟)
منظومة برمجية تُحوّل **أكوام وثائق قضية** (PDF ممسوحة، صور، أرشيفات) إلى **حزمة وثائقية
منظّمة قابلة للمراجعة**: فهرس موحّد + بطاقة تعريف لكل وثيقة + تفريغ نصّي + ملحق مالي +
تقارير جودة. تعمل **محلياً بالكامل** (لا تخرج البيانات)، وتُقدَّم كـ**سكربتات** أو
**خدمة REST API داخل حاوية Docker** قابلة للإدراج في أي منصة.

**المبدأ الحاكم**: سلامة النص أولاً — لا اختلاق، لا إعادة صياغة، لا حذف مضمون؛ وكل
موضع مشكوك فيه يُعلَّم للمراجعة البشرية ويُسجَّل في التقارير.

---

## 2) المعمارية (طبقات مستقلة)
```
[إدخال: PDF/صور/أرشيفات]
        │
        ▼
(1) استخراج النص  ── OCR محلي معزّز (Tesseract ara) + خيار نموذج رؤية (lift) للحقول المهيكلة
        │
        ▼
(2) التطبيع والتنظيف ── NFKC، إزالة التشكيل/التطويل، تصحيح اتجاه RTL، إزالة رموز OCR التالفة
        │
        ▼
(3) الاستخراج والتصنيف ── كيانات (أطراف/تواريخ/مبالغ/محاكم/مواد)، نوع المستند، بطاقة تعريف
        │
        ▼
(4) التحليل ── خط زمني، أسباب نقض، إحالات نظامية، تكرارات، صفحات فارغة/مشوّهة
        │
        ▼
(5) التوليد ── حزمة Word/PDF/HTML (فهرس جدولي + بطاقات + تفريغ) + ملحق مالي + Excel/CSV/JSON + تقارير
        │
        ▼
(6) التغليف ── ZIP للمخرجات   |   أو   خدمة API (مهام غير متزامنة)
```

**نمط التصميم**: مُوجَّه بالإعداد (Config-driven). المنطق عام، والخاص بكل قضية في
`case_config.json` فقط (رقم القضية، الأطراف، الصكوك، الشركة). إن غاب، يكتشف النظام
الأطراف من النص آلياً.

## 3) آلية العمل خطوة بخطوة
1. **القراءة**: لكل ملف، تحويل صفحاته إلى صور (pdf2image/Poppler) عند الحاجة.
2. **OCR معزّز**: لكل صفحة تُجرّب عدّة استراتيجيات معالجة صور (تباين/عتبة Otsu/تكبير+حدّة/
   إزالة تشويش) × عدّة أوضاع Tesseract (psm/oem)، ويُختار **النص الأعلى جودة** وفق معادلة
   موثّقة. (300–400 DPI.)
3. **معادلة الجودة (قابلة للتكرار)**:
   `الجودة = 100×(0.55×نسبة_الحروف_العربية + 0.30×انتظام_الأسطر − 20×نسبة_الرموز_الغريبة − 0.15×نسبة_التقطيع)`
   تُحسب لكل صفحة (0–100) وتُشتقّ منها **درجة خطر** ودرجة وصفية (ممتازة/جيدة/.../فشل).
4. **قاعدة الاستبدال**: عند إعادة OCR لنص قديم، لا يُستبدل إلا إذا تجاوزت جودة الجديد
   القديمَ بفارق > عتبة `delta`؛ وتُحفظ **النسختان** مع درجتيهما (لا فقد).
5. **التنظيف وإعادة التدفّق**: توحيد المسافات، ضبط الترقيم، إزالة محارف الاتجاه/الرموز
   التالفة، **طيّ التكرار** (كلمة/سطر مكرَّر متتالٍ)، ودمج الأسطر المتقطّعة في فقرات
   (إصلاح ظاهرة «كلمة في كل سطر»).
6. **الاستخراج**: كيانات قانونية (أطراف، أرقام قضايا/صكوك، تواريخ هجرية/ميلادية، مبالغ،
   محاكم، أنظمة، مواد)، وتصنيف نوع المستند (عنوان أولاً ثم قرائن المتن)، وبناء **بطاقة
   تعريف موحّدة** من «منطقة الترويسة» (أعلى المستند) لا من المتن.
7. **معالجة الترويسات**: كشف الترويسات/التذييلات المكرّرة وإزالتها من المتن بعد تسجيلها،
   ونقل بياناتها المهمة (محكمة/دائرة/رقم صك/تاريخ) إلى البطاقة.
8. **اختلاط الاتجاه (RTL/LTR)**: كشف الأسطر المختلطة وتعليمها للمراجعة — **بلا عكس آلي**
   (لتفادي إفساد الأرقام/الأسماء)؛ تصحيح الاتجاه يتم على مستوى العرض في Word (RTL/CS font).
9. **التكرارات والصفحات**: كشف النسخ المتطابقة/شبه المتطابقة (difflib) دون حذف، وكشف
   الصفحات الفارغة/المشوّهة وتسجيلها.
10. **التوليد**: حزمة وثائقية (فهرس جدولي قابل للنقر + بطاقة + تفريغ لكل وثيقة، كل وثيقة
    في صفحة جديدة)، **ملحق مالي** (جداول مبالغ مستخرجة بالامتناع عن التواريخ/المراجع)،
    وفهرس/بطاقات Excel/CSV/JSON، وتقارير جودة/تشوّه/تكرار/مراجعة.

## 4) الخصائص الرئيسية
- **محلي بالكامل وآمن** (سرّية القضايا).
- **OCR عربي معزّز متعدّد الاستراتيجيات** + معادلة جودة رقمية قابلة للضبط.
- **محافَظة صارمة**: لا اختلاق، لا حذف؛ تعليم وتسجيل لكل اشتباه؛ حفظ النسخ القديمة.
- **معرّفات ثابتة** لكل وثيقة (`DOC-001…`) وتتبّع للمصدر.
- **مخرجات متعدّدة الصيغ**: Word، PDF (قابل للبحث + إشارات مرجعية)، HTML (روابط داخلية)،
  Excel، CSV، JSON.
- **روابط داخلية**: فهرس ← بطاقة ← تفريغ، وعودة للفهرس (Word bookmarks/hyperlinks،
  HTML anchors، PDF outlines).
- **تقسيم أجزاء**: حزمة كاملة + أجزاء حسب النوع (لتفادي تعليق الأجهزة بالملفات الضخمة).
- **ملحق مالي** يحوّل التقييمات/الكشوفات إلى جداول مبالغ.
- **مُوجَّه بالإعداد** (قابل لإعادة الاستخدام لأي قضية) + **اكتشاف أطراف آلي**.
- **خدمة API + Docker** بنمط مهام غير متزامن ومفتاح وصول اختياري.
- **محرّك رؤية اختياري (Datalab lift)** للحقول المهيكلة مع **الامتناع** (null لا اختلاق).

## 5) بنية الكود والملفات
```
engine/                         # المحرّك (Python، عام لأي قضية)
  audit_case.py                 # تطبيع + استخراج كيانات + تصنيف (يقرأ case_config.json)
  improve_readability.py        # تصحيح اتجاه النص العربي الممسوح (قاموسي، سطراً بسطر)
  process_binaries.py           # فكّ أرشيفات (zip/rar/7z) + OCR للصور/الـPDF الممسوح
  reocr_pilot.py / reocr_hard.py / reocr_generalize.py  # محرّك OCR محلي معزّز + معادلة الجودة
  legal_clean.py                # تنظيف + RTL + إعادة تدفّق + طيّ تكرار
  legal_package.py              # الحزمة الوثائقية (فهرس جدولي + بطاقات + تفريغ + تقسيم أجزاء)
  financial_annex.py            # الملحق المالي (جداول مبالغ)
  make_master_excel.py / make_word.py  # مخرجات Excel/Word + بناء البطاقة
  analyze_case.py / case_brief.py / qc_readability.py / detect_parties.py / ...
  lift_engine.py                # محرّك رؤية اختياري (Datalab lift) — schema + adapter
service/                        # خدمة REST API
  app.py                        # FastAPI: /jobs، /jobs/{id}، /result، /health، /log
  pipeline.py                   # تشغيل المحرّك لكل مهمّة بمعزل (CASE_ROOT خاص)
  Dockerfile                    # حاوية متكاملة (tesseract-ara, poppler, libreoffice, خطوط)
  requirements.txt  README_INTEGRATION.md
case_config.template.json       # قالب إعداد القضية
```

## 6) واجهة الخدمة (API)
| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET | `/health` | جاهزية الخدمة |
| POST | `/jobs` | رفع ملفات (multipart) → إنشاء مهمّة → `job_id` |
| GET | `/jobs/{id}` | الحالة: `queued/running/done/error` |
| GET | `/jobs/{id}/result` | تنزيل حزمة المخرجات (ZIP) عند `done` |
| GET | `/jobs/{id}/log` | سجل المعالجة |

- نمط **غير متزامن** (المعالجة دقائق): ارفع → تابع → نزّل.
- مصادقة اختيارية عبر `X-API-Key` (متغيّر بيئة `API_KEY`).
- توثيق تفاعلي تلقائي على `/docs` (OpenAPI/Swagger).

## 7) المتطلبات التقنية
- **بايثون 3.9+** + مكتبات: `python-docx, openpyxl, pdf2image, Pillow, numpy`
  (+ للخدمة: `fastapi, uvicorn, python-multipart`).
- **أدوات نظام**: `tesseract-ocr` + `tesseract-ocr-ara`، `poppler-utils`،
  `libreoffice-writer` (تصدير PDF)، خط عربي حر (Amiri) للخادم.
- **الحاوية** تثبّت كل ذلك بأمر واحد.
- **اختياري (lift)**: **GPU** (~16–24GB) + حزمة النموذج؛ يبقى المسار الافتراضي CPU.

## 8) التشغيل
**خدمة (موصى به للمنصّات):**
```
docker build -t legal-audit-service -f service/Dockerfile .
docker run -d -p 8080:8080 -v /srv/legal-jobs:/data/jobs -e API_KEY="سرّي" legal-audit-service
```
**يدوي (سطر أوامر):**
```
export CASE_ROOT=/path/to/case      # فيه outputs/json/full_documents.jsonl
python3 engine/legal_package.py     # الحزمة الوثائقية
python3 engine/financial_annex.py   # الملحق المالي
```

## 9) المخرجات
- `حزمة_الوثائق.docx/.pdf/.html` — الحزمة الكاملة (فهرس جدولي + بطاقات + تفريغ).
- `حزمة_الوثائق_جزءN_*.docx/.pdf` — أجزاء مقسّمة حسب النوع.
- `الملحق_المالي.docx/.xlsx` — جداول المبالغ.
- `الفهرس_الموحد.xlsx/.csv` ، `بطاقات_الوثائق.json/.xlsx`.
- تقارير: جودة الصفحات، النصوص المشوّهة، الصفحات الفارغة، التكرارات، حالات المراجعة + `document_index.json`.

## 10) محرّك الرؤية الاختياري (Datalab lift)
- نموذج رؤية مفتوح الأوزان (9B) يُعيد JSON مطابقاً لـ**schema** مع **الامتناع** (null
  بدل اختلاق الحقول الغائبة) — متوافق مع مبدأ «لا تختلق».
- يُفعَّل بـ`ENGINE_MODE=lift` (يتطلّب GPU + ترخيص OpenRAIL-M المعدّل: مجاني تحت 5M$ إيراد).
- الدور: تحسين **البطاقة والمبالغ** المهيكلة؛ يبقى التفريغ الحرفي عبر OCR.
- **تراجع آمن**: عند غيابه يستمر المسار الافتراضي (Tesseract) دون خلل.
- **توصية**: اختبار على عيّنة عربية قانونية قبل الاعتماد.

---

## 11) الأمان والخصوصية والحدود
- معالجة محلية بالكامل؛ لا إرسال خارجي (المحرّك السحابي/lift اختياري وبمفتاح صريح).
- جودة المخرجات تتبع جودة المسح؛ سقف Tesseract المحلي ~85 للصفحات الأصعب.
- نطاقات الصفحات تقديرية حيث لا توجد علامات صفحات صريحة.
- **كل المخرجات تنظيمية تحتاج مراجعة المحامي، وليست رأياً قانونياً نهائياً.**

---

## 12) خارطة التطوير المقترحة
- Webhook لإشعار المنصة عند الاكتمال (بدل الاستعلام الدوري).
- طابور مهام خارجي (Redis/RQ) للتوسّع الأفقي.
- ربط lift بجداول الملحق المالي (استبدال الاستخراج بالـregex عند التفعيل).
- محرّك OCR سحابي اختياري (Azure/Google) للصفحات الأصعب عبر مفتاح صريح.
- مخزن حالة موحّد (SQLite) كمصدر حقيقة وحيد تُشتقّ منه كل التقارير.
